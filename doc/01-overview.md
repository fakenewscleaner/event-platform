# 01. 專案概述

## 這個專案是什麼

假新聞清潔劑（FNC）長期在全台各地舉辦宣講、課程等活動，
目前活動資料存放在 Airtable，志工招募、回饋、講師費追蹤散落在不同工具。
`event-platform` 的目標是建立一個自有的活動／志工平台，讓：

- **志工** 可以在一個地方看到近期活動、報名、回報成果、上傳照片、填回饋。
- **總召** 可以管理自己負責的場次、看志工組成、發通知、提物資需求。
- **講師** 可以回報講師費狀況。
- **核心夥伴／管理員** 可以管理活動、使用者、權限、回饋欄位、物資類型。
- **行銷成員** 可以根據活動回饋撰寫並發表文章。

## 設計原則

1. **Airtable 仍是活動的建檔來源（P0）。** 系統以排程同步 Airtable 的活動資料，Airtable 來的欄位在系統內唯讀；系統自己的欄位（志工需求數、給志工看的備註等）另外存放，避免雙向同步衝突。詳見 [04-airtable-sync.md](04-airtable-sync.md)。
2. **敏感資料不進系統。** 身分證、匯款帳號等一律不存。講師費相關欄位只有 Admin / Core 可見。
3. **權限採角色制。** 七種角色，Volunteer 是所有登入使用者的基礎權限。詳見 [02-roles-and-permissions.md](02-roles-and-permissions.md)。
4. **模組化。** 資料表、migration、程式碼依模組分拆，讓可讀性高、可以分批上線。詳見 [05-modules.md](05-modules.md)。

## 使用者角色

| 角色 | 英文 | 說明 |
| --- | --- | --- |
| 系統管理員 | Admin | 原則上一律通過 |
| 核心夥伴 | Core | 除不該動的系統功能，其餘都有 |
| 總召 | Coordinator | 負責特定場次的志工，對該場次有額外權限 |
| 講師 | Lecturer | 活動講師，可回報講師費 |
| 志工 | Volunteer | 所有登入使用者都有的基礎權限 |
| 未登入 | Guest | 只能看公開頁面 |
| 行銷成員 | Marketer | 最小權限原則，只能操作行銷文章 |

## 模組總覽

| 模組 | 說明 | 相依 |
| --- | --- | --- |
| 活動核心 | 活動資訊、地點、志工報名參加 | — |
| 使用者核心 | 建立使用者、登入、角色 | — |
| 回饋 | 志工上傳照片、填回饋表單、統計 KPI | 活動 |
| 通知 | 總召發活動修正通知，自動通知所有報名志工 | 活動 |
| 公佈欄 | 登入後首頁公佈給志工的資訊 | — |
| 總召 | 活動自訂總召、總召特別權限 | 活動 |
| 講師 | 活動自訂講師、講師相關權限 | 活動 |
| 講師費 | 講師費追蹤 | 活動、講師 |
| 物資 | 物資類型管理、活動物資需求 | 活動 |
| 行銷 | 行銷文章撰寫與發表 | 回饋 |

## 開發階段

| 階段 | 範圍 |
| --- | --- |
| P0 | 工程基礎建設（Laravel、Docker Compose、migration、Airtable 同步）、首頁、公佈欄、近期活動、活動詳情、報名／取消、我的活動、活動編輯 |
| P1 | 回報模組（回饋、照片、成果數）、講師費、總召場次、物資、行銷文章、後台管理 |
| P2 | 發佈更新通知等進階功能 |

細節見 [08-roadmap.md](08-roadmap.md)。
